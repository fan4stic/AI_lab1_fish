## 1. Постановка задачи

Требуется построить воспроизводимую регрессионную модель, которая по морфологическим признакам рыбы предсказывает её массу. Модель обучается на данных, исследованных в лабораторной работе №1, и фиксируется в MLflow.

**Целевая переменная:** `Weight` — масса рыбы в граммах.

**Признаки:**

- числовые: `Length3` (длина), `Height` (высота), `Width` (ширина) в миллиметрах;
- категориальный: `Species` (вид рыбы).

**Критерии успеха:**

- тест R² ≥ 0.85 на замороженной тестовой выборке;
- MAE ≤ 100 г;
- модель превосходит наивные baseline (E0) по MSE;
- все прогнозы физически осмысленны (масса > 0 г и < 5000 г);
- эксперимент воспроизводим: одинаковый seed и разбиение дают одинаковые метрики.

## 2. Данные, разбиение и проверки качества

### 2.1. Данные

Источник — учебный набор Fish Market (Токио, Япония). В репозитории:

- `data/fish_participant.csv` — 111 строк, 7 колонок;
- `data/fish_holdout_demo.csv` — 28 строк для быстрой проверки инференса.

Пропусков нет. Подробное описание полей, единиц измерения, диапазонов и ролей каждой колонки — в `data/README.md`.

**Исключённые признаки:** `Length1` и `Length2` не используются, потому что сильно коллинеарны с `Length3` (corr > 0.99). Это подтверждено в EDA-ноутбуке `notebooks/data_analysis_and_model_selection.ipynb`.

**Асимметрия целевой переменной:** распределение `Weight` имеет сильную правостороннюю асимметрию (min = 5.9 г, max = 1550 г). Из-за этого в моделях E1–E4 применяется преобразование `log1p(Weight)` с обратным `expm1` через `TransformedTargetRegressor`.

### 2.2. Разбиение

Тестовая выборка **заморожена** до подбора признаков и гиперпараметров:

    train_test_split(test_size=0.2, random_state=42)

Итог: **train = 88 строк, test = 23 строки**. Индексы сохранены в `runs/split_indices.csv`, есть проверка на непересечение.

Кросс-валидация — **GroupKFold(n_splits=5)** с группами по `Species`. Такой выбор объясняется тем, что модель проверяется на незнакомых видах рыб: если признак `Species` критичен для качества, GroupKFold покажет это честно. Недостаток: в датасете 7 видов, поэтому некоторые фолды содержат 1–2 вида, что повышает стандартное отклонение метрик между фолдами.

### 2.3. Проверки качества

- Отсутствие пропусков — проверено (`data.isnull().sum()` = 0 по всем колонкам).
- Отсутствие отрицательных значений в числовых признаках — проверено.
- Согласованность длины и высоты — визуально проверено в EDA-ноутбуке.
- Физическая осмысленность прогнозов — проверено в `src/evaluate.py`: 0 прогнозов ≤ 0 г, 0 прогнозов > 5000 г.
- Отсутствие пересечения train и test — покрыто тестом `tests/test_pipeline.py::test_train_test_indices_disjoint`.

## 3. Базовое решение и изменения относительно исходного проекта

### 3.1. Baseline (что было)

Исходный проект содержал:

- препроцессинг в `src/preprocess.py` (функции `handle_outlier` и `prep_data`) — вне Pipeline, применялся напрямую к DataFrame;
- обучение в `src/train.py` с `FunctionTransformer(np.log)` на всех числовых признаках и `TransformedTargetRegressor(log, exp)` на целевой;
- ручное удаление выбросов (`df.drop([13])`);
- управление окружением через `Pipfile`;
- сохранение модели в `reg.joblib`;
- ноутбук `data_analysis_and_model_selection.ipynb`, в котором EDA и обучение моделей (Linear, Lasso, RandomForest) смешаны.

### 3.2. Что изменено

1. **Препроцессинг** перенесён в `ColumnTransformer` + `Pipeline`:
   - числовые признаки: `SimpleImputer(strategy="median")` + `StandardScaler`;
   - категориальные: `SimpleImputer(strategy="most_frequent")` + `OneHotEncoder(handle_unknown="ignore")`.
   Это соответствует требованиям пункта 4 раздела 2.1 задания: кодировщик, заполнение пропусков и масштабирование настраиваются внутри каждой итерации кросс-валидации как единая цепочка преобразований.

2. **Трансформация целевой переменной** — `log1p` / `expm1` вместо `log` / `exp`. Это корректно работает с массой меньше 1 г и стабильнее на малых значениях.

3. **Ручное удаление выбросов** убрано. Вместо него — регуляризация (Ridge) и `log1p` на целевую. Такой подход устойчивее и не требует ручного вмешательства, которое невозможно воспроизвести на новых данных.

4. **Логика обучения вынесена из ноутбука** в `src/train.py`, EDA — оставлен в ноутбуке. Ноутбук больше не содержит `fit` и `dump`, что соответствует требованию «блокнот Jupyter только для анализа, без скрытой обязательной логики обучения».

5. **Эксперименты E0–E4** вместо одной модели: наивный baseline, линейная регрессия, Ridge с подбором alpha, HistGradientBoosting, эксперимент без `Species`.

6. **Кросс-валидация GroupKFold по `Species`** вместо одиночного разбиения. Модель проверяется на незнакомых видах рыб.

7. **MLflow** для логирования параметров, метрик, артефактов и сохранённых моделей.

8. **Окружение** переведено на `venv` + `requirements.txt` (`Pipfile` удалён). Это одно явное описание окружения вместо двух.

9. **Минимальные тесты** в `tests/test_pipeline.py` (6 тестов, покрывают раздел 7 задания).

10. **Конфигурация эксперимента** вынесена в `configs/train.yaml`: seed, признаки, разбиение, гиперпараметры моделей.

## 4. Эксперименты E0–E4

Все эксперименты используют **одно и то же разбиение** и **один и тот же препроцессинг**, отличаются только моделью и, в E4, набором признаков.

| ID | Модель | Признаки | Целевая |
|---|---|---|---|
| E0 | `DummyRegressor(mean)`, `DummyRegressor(median)` | все | без преобразования |
| E1 | `LinearRegression` | все | `log1p` |
| E2 | `Ridge` (GridSearchCV по alpha) | все | `log1p` |
| E3 | `HistGradientBoostingRegressor` (GridSearchCV по max_iter, learning_rate, max_depth) | все | `log1p` |
| E4 | `LinearRegression` | без `Species` | `log1p` |

### 4.1. Таблица метрик

| Эксперимент | CV MSE mean | CV MSE std | Test MSE | Test MAE | Test R² |
|---|---|---|---|---|---|
| **E3_hist_gb_log1p** | **26 447.8** | 28 457.9 | **12 436.2** | **73.27** | **0.8891** |
| E2_ridge_log1p | 28 860.4 | 33 964.6 | 16 166.5 | 121.12 | 0.8558 |
| E0_dummy_mean | 129 533.3 | 41 717.5 | 123 245.5 | 284.72 | −0.0992 |
| E0_dummy_median | 144 488.1 | 9 375.8 | 157 828.6 | 302.17 | −0.4077 |
| E4_linear_no_species | 301 967.1 | 417 337.7 | 140 934.2 | 200.80 | −0.2570 |
| E1_linear_log1p | 670 180.8 | 1 183 841.0 | 51 382.7 | 115.45 | 0.5417 |

### 4.2. Наблюдения

- **E3 (бустинг) — лучшая модель** по всем метрикам. Test R² = 0.89, MAE = 73 г.
- **E2 (Ridge) — второй результат**, но уступает E3 по MAE в ~1.7 раза.
- **E0 (dummy)** даёт отрицательный R² на тесте: модель, предсказывающая среднее или медиану train, хуже константного прогноза среднего теста. Это подтверждает, что обученные модели реально полезны.
- **E1 (линейная регрессия)** на CV нестабильна: `cv_mse_std` больше среднего. Причина — в GroupKFold один из фолдов попадает на редкие виды, где линейная регрессия без регуляризации выдаёт абсурдно большие прогнозы. Ridge (E2) и бустинг (E3) устойчивы к этому.
- **E4 (без Species)** — R² = −0.26, модель хуже константного прогноза. Это сильное доказательство, что вид рыбы критичен для качества.

### 4.3. Воспроизводимость

- Seed = 42 применяется к Python, NumPy и sklearn.
- Одно разбиение train/test, зафиксированное в `runs/split_indices.csv`.
- Один и тот же `GroupKFold(n_splits=5)` для всех экспериментов.
- MLflow-теги содержат `git_commit`, `python_version`, `sklearn_version`, `mlflow_version`, `pandas_version`.
- Хеш данных `data_sha256` зафиксирован в параметрах каждого запуска.

Повторный запуск `python src/train.py` даёт идентичные метрики.

## 5. Анализ ошибок

Анализ выполнен в `src/evaluate.py` для лучшей модели E3. Артефакты:

- `runs/top_errors.csv` — топ-5 крупнейших ошибок;
- `runs/mae_by_species.csv` — MAE по видам;
- `runs/mae_by_size.csv` — MAE по диапазонам длины;
- `reports/figures/best_model_residuals.png` — график остатков;
- `reports/figures/best_model_pred_vs_true.png` — прогноз vs истина;
- `reports/figures/best_model_top_errors.png` — топ-5 ошибок.

### 5.1. График остатков и систематические зоны

График `best_model_residuals.png` показывает, что модель:

- **недооценивает крупную рыбу**: остатки положительные при больших значениях прогноза. Крупнейшая ошибка — Pike с истинным весом 1250 г, модель предсказала 859 г, остаток +391 г.
- **переоценивает часть средних экземпляров**: остатки отрицательные. Например, Bream с истинным весом 340 г — модель предсказала 591 г, остаток −251 г.

Ошибка **растёт с размером** рыбы (см. 5.3), что подтверждает систематическую зону ошибки в области крупных экземпляров.

### 5.2. Топ-5 крупнейших абсолютных ошибок

| Species | Length3 | Height | Width | y_true | y_pred | residual |
|---|---|---|---|---|---|---|
| Pike | 59.7 | 10.69 | 6.98 | 1250.0 | 858.6 | +391.4 |
| Bream | 37.3 | 13.91 | 5.07 | 340.0 | 591.2 | −251.2 |
| Bream | 37.2 | 15.44 | 5.58 | 600.0 | 714.7 | −114.7 |
| Perch | 39.0 | 10.88 | 6.86 | 685.0 | 772.5 | −87.5 |
| Bream | 45.9 | 18.64 | 6.75 | 975.0 | 890.2 | +84.8 |

**Что обращает внимание:**

- Три из пяти крупнейших ошибок — Bream: две переоценки, одна недооценка.
- Pike недооценён на 391 г, что составляет 31 % от истинной массы.
- Один объект (Bream, Length3 = 37.3, y_true = 340 г) выглядит аномалией: Bream такой длины обычно весит 500–700 г. Возможно, это ошибка измерения.

### 5.3. MAE по видам и по диапазонам размера

**MAE по видам (тест, 23 объекта):**

| Species | n | MAE, г |
|---|---|---|
| Smelt | 2 | 11.3 |
| Whitefish | 2 | 26.8 |
| Parkki | 1 | 38.1 |
| Roach | 3 | 39.4 |
| Perch | 5 | 54.3 |
| Bream | 8 | 89.0 |
| **Pike** | 2 | **234.5** |

**Проблемные виды** — Pike и Bream. Pike — самый крупный вид в датасете (до 1550 г), и модель систематически его недооценивает. Bream занимает 8 из 23 объектов теста и «тянет» общий MAE.

**MAE по диапазонам длины (квартили `Length3`):**

| Диапазон | n | Length3, мм | MAE, г |
|---|---|---|---|
| small | 8 | 13.1–29.3 | 31.2 |
| medium | 7 | 30.6–37.3 | 80.9 |
| large | 8 | 38.3–59.7 | 108.6 |

**MAE растёт почти линейно с размером.** Модель хорошо работает на мелких рыбах и плохо — на крупных. Причина — мало крупных экземпляров в train.

### 5.4. Проверка физической осмысленности прогнозов

    Всего прогнозов: 23
    Прогнозов ≤ 0 г: 0
    Прогнозов > 5000 г: 0

Модель физически корректна: все прогнозы лежат в осмысленном диапазоне.

### 5.5. Источник ошибки: данные, модель или постановка

Анализ показывает три источника.

**Данные.** Крупные экземпляры (Pike > 1000 г, Bream с Height > 18 мм) в датасете представлены единичными строками. Их доля в train мала, поэтому модель плохо на них обобщается. Один из топ-5 объектов (Bream, y_true = 340 г, Length3 = 37.3) выглядит как аномалия измерения.

**Модель.** Используется `log1p` на целевую переменную. Это стабилизирует обучение при правосторонней асимметрии, но обратное преобразование `expm1` **сглаживает крупные прогнозы**, занижая их. Отсюда систематическая недооценка Pike и больших Bream. Это ограничение выбранного подхода, а не случайный шум.

**Постановка задачи.** Вес рыбы зависит не только от длины, высоты и ширины, но и от сезона (икра, жирность), возраста, состояния. Этих признаков в датасете нет. Учитывая это, MAE = 73 г и R² = 0.89 — хороший результат для такой постановки.

### 5.6. Следующий эксперимент

**Гипотеза:** систематическую недооценку крупной рыбы можно уменьшить, если обучать отдельные модели для разных групп видов.

**Что сделать:** обучить две модели — для «мелких» видов (Smelt, Roach, Parkki) и для «крупных» (Pike, Bream, Perch, Whitefish). Разбиение train/test оставить тем же, сравнить метрики с E3.

**Ожидаемый результат:**

- MAE по Pike снизится с 234 до < 200 г;
- MAE по Bream снизится с 89 до < 70 г;
- общий MAE достигнет 55–65 г;
- test MSE упадёт до 8000–10000;
- R² вырастет до 0.92–0.94.

**Альтернатива:** оставить одну модель, но применить bias correction при обратном преобразовании `log1p → expm1` — добавить к прогнозу средний остаток на train. Это уменьшит систематическую недооценку без усложнения архитектуры.


## 6. Воспроизведение

### 6.1. Окружение

- Python 3.12;
- зависимости: `pandas`, `numpy`, `scikit-learn`, `joblib`, `matplotlib`, `seaborn`, `jinja2`, `mlflow`, `pyyaml`, `ipykernel`, `pytest`.

Установка:

    python -m venv .venv
    .\.venv\Scripts\Activate.ps1        # Windows PowerShell
    pip install -r requirements.txt

Для Linux / macOS вторая строка будет `source .venv/bin/activate`.

### 6.2. Запуск экспериментов

    python src/train.py

Скрипт:

1. Загружает `configs/train.yaml`.
2. Делает замороженное разбиение train/test с seed 42.
3. Обучает E0–E4 с кросс-валидацией GroupKFold по `Species`.
4. Логирует параметры, метрики, артефакты и модели в MLflow (папка `mlruns/`).
5. Сохраняет лучшую модель в `models/best_model.joblib`.
6. Сохраняет сводную таблицу метрик в `runs/summary.csv`.

### 6.3. Анализ ошибок

    python src/evaluate.py

Сохраняет:

- `runs/top_errors.csv` — топ-5 крупнейших ошибок;
- `runs/mae_by_species.csv` — MAE по видам;
- `runs/mae_by_size.csv` — MAE по диапазонам длины;
- `reports/figures/best_model_residuals.png`, `best_model_pred_vs_true.png`, `best_model_top_errors.png` — графики.

### 6.4. Тесты

    pytest tests/ -v

6 тестов, покрывают раздел 7 задания:

- индексы train и test не пересекаются;
- pipeline принимает строку с неизвестной категорией;
- число прогнозов равно числу входных строк, все значения конечны;
- метрики на фиксированном примере совпадают с ручным расчётом;
- сохранённый pipeline после загрузки воспроизводит прогноз;
- pipeline корректно обрабатывает пропуски.

### 6.5. Просмотр журнала MLflow

    $env:MLFLOW_ALLOW_FILE_STORE = "true"
    mlflow ui --backend-store-uri mlruns --workers 1

Открыть в браузере `http://127.0.0.1:5000`, выбрать эксперимент `fishgrow-lab02`. В нём видны все 6 запусков E0–E4 с параметрами, метриками, тегами и артефактами.

Экспорт метаданных запусков сохранён в `reports/mlflow_runs_export.csv`, скриншоты UI — в `reports/screenshots/`.

### 6.6. Что должно получиться

При запуске из чистого окружения на тех же данных воспроизводятся все метрики в разделах 4 и 5, потому что seed, разбиение и гиперпараметры зафиксированы. Если данные изменятся, их хеш `data_sha256` в MLflow тоже изменится, что сигнализирует о несравнимости метрик.
